# SyncTalk MVP PRD

## 1. 产品定位

SyncTalk MVP 是一个面向语言学习场景的社交协作平台。第一版目标是跑通从账号注册、语言资料完善、资料匹配、好友建立，到一对一文字聊天和视频练习的完整闭环。

MVP 不追求复杂推荐算法，也不直接引入 Agent。资料匹配第一版采用规则匹配，后续可以平滑升级为 Agent 匹配、推荐解释和破冰建议。

核心流程：

```txt
注册登录 -> 完善资料 -> 资料匹配 -> 发送好友请求 -> 成为好友 -> 文字聊天 / 视频通话
```

## 2. MVP 功能列表

第一版围绕五个核心功能展开：

1. 注册登录
2. 资料匹配
3. 好友系统
4. 聊天功能
5. 视频功能

支撑体验模块：

- 站内通知：承载好友请求、请求接受、未读消息和视频呼叫提示。
- 主题切换：支持基础主题切换。
- 响应式布局：保证桌面端和移动端核心流程可用。
- 基础错误提示：覆盖表单、权限、网络、实时连接等常见异常。

## 3. 页面列表

### 登录页

建议路径：

```txt
/auth/login
```

功能：

- 用户登录。
- 跳转注册页。
- 展示登录错误提示。
- 登录成功后进入应用主流程。

### 注册页

建议路径：

```txt
/auth/register
```

功能：

- 创建账号。
- 注册成功后进入资料配置页。
- 展示注册错误提示。

### 资料页

建议路径：

```txt
/app/profile
```

功能：

- 填写和编辑语言学习资料。
- 配置母语、目标语言、语言等级、学习目标、个人简介和时区。
- 保存成功后进入资料匹配页。

### 资料匹配页

建议路径：

```txt
/app/discover
```

功能：

- 展示基于资料规则生成的匹配用户列表。
- 展示匹配理由和用户基础资料。
- 支持按关键词搜索用户。
- 展示关系状态并允许发送好友请求。

### 好友页

建议路径：

```txt
/app/friends
```

功能：

- 查看好友列表。
- 移除好友。
- 从好友列表进入聊天或视频通话。

### 好友请求页

建议路径：

```txt
/app/requests
```

功能：

- 查看收到的好友请求。
- 接受好友请求。
- 拒绝好友请求。
- 查看已发送请求状态。

### 聊天页

建议路径：

```txt
/app/chat/:friendId
```

功能：

- 查看当前好友信息。
- 加载历史消息。
- 发送文字消息。
- 实时接收文字消息。
- 从聊天页发起视频通话。

### 视频通话页

建议路径：

```txt
/app/call/:friendId
```

功能：

- 发起一对一视频通话。
- 加入一对一视频通话。
- 展示通话状态和参与者状态。
- 控制麦克风、摄像头和挂断操作。

### 设置页

建议路径：

```txt
/app/settings
```

功能：

- 切换主题。
- 查看当前登录用户。
- 退出登录。

## 4. 用户流程

### 新用户流程

```txt
进入注册页
-> 输入用户名、邮箱和密码
-> 注册成功
-> 进入资料页
-> 完善语言学习资料
-> 进入资料匹配页
-> 查看匹配用户并发送好友请求
```

### 老用户流程

```txt
进入登录页
-> 输入账号和密码
-> 登录成功
-> 进入资料匹配页或好友页
-> 查看匹配用户 / 好友列表
-> 进入聊天或视频通话
```

### 资料匹配流程

```txt
用户填写语言学习资料
-> 系统按规则生成匹配列表
-> 用户查看匹配理由
-> 用户向合适对象发送好友请求
```

### 添加好友流程

```txt
用户 A 在资料匹配页或搜索结果中看到用户 B
-> 用户 A 发送好友请求
-> 用户 B 在好友请求页或站内通知中看到请求
-> 用户 B 接受请求
-> 用户 A 和用户 B 出现在彼此好友列表中
```

### 聊天流程

```txt
用户从好友列表点击某个好友
-> 进入一对一聊天页
-> 系统加载历史消息
-> 用户发送文字消息
-> 对方实时收到消息
```

### 视频通话流程

```txt
用户从好友列表或聊天页发起视频通话
-> 对方收到站内呼叫提示
-> 对方加入通话
-> 双方进行一对一视频练习
-> 任意一方挂断后结束通话
```

## 5. 功能输入输出

### 注册登录

输入：

- 注册用户名。
- 注册邮箱。
- 注册密码。
- 登录账号：用户名或邮箱。
- 登录密码。

输出：

- 用户账号。
- 登录态 Cookie。
- 当前用户信息。
- 登录或注册错误提示。
- 登录态过期状态。

状态：

- 未登录。
- 登录中。
- 已登录。
- 登录失败。
- 登录态过期。

### 资料匹配

输入：

- 母语。
- 目标语言。
- 语言等级。
- 学习目标。
- 个人简介。
- 时区。
- 搜索关键词：用户名、语言或简介关键词。

输出：

- 用户语言学习资料。
- 匹配用户列表。
- 匹配理由。
- 用户基础信息：头像、用户名、母语、目标语言、语言等级、学习目标、时区。
- 关系状态：陌生人、已发送请求、收到请求、已是好友。

匹配规则：

```txt
第一版采用规则匹配：
语言互补优先，其次考虑目标语言一致、语言等级接近、学习目标相似、时区接近。
```

状态：

- 资料未完善。
- 匹配加载中。
- 有匹配结果。
- 无匹配结果。
- 匹配加载失败。

### 好友系统

输入：

- 目标用户 ID。
- 发送好友请求操作。
- 接受好友请求操作。
- 拒绝好友请求操作。
- 移除好友操作。

输出：

- 好友请求记录。
- 好友关系记录。
- 好友列表。
- 请求状态：pending、accepted、rejected。
- 操作成功或失败提示。

状态：

- 陌生人。
- 已发送请求。
- 收到请求。
- 已是好友。
- 请求已处理。
- 操作失败。

### 聊天功能

输入：

- 好友 ID。
- 文本消息内容。

输出：

- 一对一聊天频道。
- 历史消息列表。
- 新发送消息。
- 实时接收消息。
- 发送失败状态。

约束：

- 非好友不能进入聊天。
- 空消息不能发送。
- 同一对好友始终进入同一个聊天频道。

频道规则：

```txt
将两个用户 ID 排序后拼接，生成固定的一对一频道 ID。
```

状态：

- 频道加载中。
- 频道加载失败。
- 消息发送中。
- 消息发送成功。
- 消息发送失败。
- 实时连接断开。

### 视频功能

输入：

- 好友 ID。
- 发起通话操作。
- 加入通话操作。
- 挂断通话操作。
- 麦克风开关。
- 摄像头开关。

输出：

- 一对一通话会话。
- 通话状态。
- 参与者状态。
- 设备状态。
- 通话失败状态。

约束：

- 非好友不能进入视频通话。
- 同一对好友使用稳定的一对一 call ID。
- MVP 只做一对一视频通话，不做多人会议。

通话 ID 规则：

```txt
将两个用户 ID 排序后拼接，生成固定的一对一 call ID。
```

状态：

- 等待呼叫。
- 呼叫中。
- 加入中。
- 通话中。
- 对方已挂断。
- 设备不可用。
- 通话连接失败。

### 通知模块

输入：

- 好友请求事件。
- 好友接受事件。
- 未读消息事件。
- 视频呼叫事件。
- 标记已读操作。

输出：

- 站内通知列表。
- 未读提示。
- 通知跳转目标。
- 已读状态。

状态：

- 无通知。
- 有未读通知。
- 通知加载失败。
- 通知已读。

## 6. MVP 范围

第一版必须包含：

- 用户注册。
- 用户登录。
- 登录态校验。
- 退出登录。
- 语言学习资料填写和编辑。
- 基于资料的规则匹配。
- 匹配用户列表和匹配理由。
- 用户搜索。
- 发送好友请求。
- 接受和拒绝好友请求。
- 好友列表。
- 移除好友。
- 一对一实时文字聊天。
- 历史消息加载。
- 一对一视频通话。
- 麦克风和摄像头基础控制。
- 站内通知和未读提示。
- 基础错误提示。
- 主题切换。
- 基础响应式布局。

第一版目标：

```txt
用户可以注册账号、完善语言资料、匹配语伴、建立好友关系，并通过文字聊天或视频通话进行语言练习。
```

## 7. MVP 不做什么

MVP 不包含：

- AI Agent 自动匹配。
- AI 推荐解释。
- AI 破冰话题。
- AI 聊天总结。
- 学习卡片。
- 浏览器 Push。
- 邮件或短信通知。
- 群聊。
- 多人视频会议。
- 动态广场。
- 好友备注。
- 好友分组。
- 拉黑或举报。
- 管理后台。
- 付费系统。

这些功能属于后续模块，不进入第一版 MVP。

## 8. 基础错误处理

### 注册登录错误

需要处理：

- 邮箱已被注册。
- 用户名已被占用。
- 密码为空或长度不足。
- 登录账号不存在。
- 密码错误。
- 登录态过期。

处理方式：

- 显示清晰的表单级错误信息。
- 登录态过期时跳转登录页。

### 资料匹配错误

需要处理：

- 必填资料缺失。
- 匹配结果为空。
- 匹配列表加载失败。
- 用户搜索自己。
- 目标用户已经是好友。
- 已经发送过好友请求。

处理方式：

- 资料缺失时引导用户回到资料页补全。
- 没有结果时展示空状态。
- 已是好友或已发送请求时禁用重复操作。

### 好友系统错误

需要处理：

- 重复发送好友请求。
- 好友请求不存在。
- 好友请求已被处理。
- 用户尝试添加自己。
- 移除好友失败。

处理方式：

- 显示操作失败原因。
- 操作成功后刷新好友列表、请求列表和通知状态。

### 聊天错误

需要处理：

- 非好友不能进入聊天。
- 空消息不能发送。
- 消息发送失败。
- 聊天频道加载失败。
- 网络断开。

处理方式：

- 非好友访问聊天页时展示无权限状态。
- 空消息时禁用发送按钮。
- 消息发送失败时展示失败状态。
- 网络异常时提示稍后重试。

### 视频错误

需要处理：

- 非好友不能进入视频通话。
- 通话会话加载失败。
- 麦克风或摄像头不可用。
- 对方未加入或已挂断。
- 通话连接失败。

处理方式：

- 非好友访问视频页时展示无权限状态。
- 设备不可用时展示设备错误提示。
- 通话连接失败时允许用户返回聊天页或重新发起。

### 通知错误

需要处理：

- 通知列表加载失败。
- 通知跳转目标不存在。
- 标记已读失败。

处理方式：

- 加载失败时展示重试入口。
- 跳转目标不存在时展示无效通知状态。
- 标记已读失败时保留原未读状态。

## 9. 验收标准

MVP 完成时应满足：

- 用户可以注册、登录、退出，并在刷新页面后恢复登录态。
- 未登录用户不能进入 `/app` 下的主应用页面。
- 用户可以填写和编辑语言学习资料。
- 资料未完善时，系统能引导用户补全资料。
- 用户可以看到基于资料规则生成的匹配用户列表。
- 匹配结果能展示清晰的匹配理由。
- 用户可以搜索其他用户。
- 用户不能添加自己。
- 用户不能重复发送好友请求。
- 用户接受请求后，双方好友列表都更新。
- 好友请求、请求接受、未读消息和视频呼叫可以形成站内通知或未读提示。
- 非好友不能进入聊天。
- 好友双方进入同一个一对一聊天频道。
- 一方发送文字消息，另一方可以实时收到。
- 非好友不能进入视频通话。
- 好友双方可以进入同一个一对一视频通话。
- 用户可以控制麦克风、摄像头和挂断操作。
- 页面在桌面端和移动端都能完成核心流程。
- 用户可以切换主题。

## 10. 后续版本方向

### V1：Agent 匹配增强

- 将规则匹配升级为 Agent 匹配。
- 根据语言资料、学习目标和历史互动生成推荐理由。
- 生成破冰话题和练习建议。

### V2：学习辅助能力

- AI 聊天总结。
- 学习卡片。
- 练习记录。
- 学习目标跟踪。

### V3：社交扩展

- 群聊。
- 多人语音或视频练习。
- 动态广场。
- 好友备注和分组。

MVP 的重点是先验证语言学习社交闭环。后续 Agent 和 AI 能力都建立在资料、好友、聊天和视频这条主链路之上。
