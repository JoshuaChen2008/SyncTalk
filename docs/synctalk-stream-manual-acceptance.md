# SyncTalk Stream Manual Acceptance

本文记录 SyncTalk MVP 的 Stream Chat / Video 双账号手动验收步骤。自动测试覆盖 token、权限、稳定 channel/call ID、基础 UI 状态；真实消息实时性和浏览器媒体能力需要在可用 Stream、MongoDB、浏览器权限环境下验收。

## 1. 环境要求

- 后端 `.env` 配置有效的 `MONGODB_URI`、`JWT_SECRET`、`CLIENT_ORIGIN`、`STREAM_API_KEY`、`STREAM_API_SECRET`。
- 前端 `.env` 配置同一个 `VITE_STREAM_API_KEY`。
- 前后端本地服务可访问，且浏览器允许当前站点使用麦克风和摄像头。
- 准备两个已完善资料并互为好友的测试账号：账号 A 和账号 B。
- 准备一个非好友账号或非好友用户 ID，用于权限失败路径。

不要把真实 `.env`、密钥、日志或临时调试输出提交到仓库。

## 2. Chat 验收

1. 使用两个浏览器上下文分别登录账号 A 和账号 B。
2. A 从好友列表进入 B 的 `/app/chat/:friendId`，B 从好友列表进入 A 的同一聊天入口。
3. 确认两边进入同一个稳定频道，页面没有权限错误或连接错误。
4. A 发送一条非空消息，确认 B 实时收到。
5. B 回复一条非空消息，确认 A 实时收到。
6. 刷新其中一个聊天页，确认历史消息仍可加载。
7. 使用非好友访问 `/app/chat/:friendId`，确认页面显示无权限状态。

通过标准：

- A/B 能实时互发消息。
- 刷新后历史消息仍存在。
- 非好友不能进入聊天。
- 浏览器控制台没有影响主流程的 error。

## 3. Call 验收

1. 使用两个浏览器上下文分别登录账号 A 和账号 B。
2. A 从好友列表进入 B 的 `/app/call/:friendId`，B 从好友列表进入 A 的同一通话入口。
3. 两边授权麦克风和摄像头。
4. 确认双方进入同一个稳定 call，并能看到或听到对方。
5. A 切换麦克风，确认本端控制状态变化，B 端通话不中断。
6. A 切换摄像头，确认本端控制状态变化，B 端通话不中断。
7. B 重复麦克风和摄像头切换。
8. A 点击挂断，确认 A 离开通话并回到好友页，B 页面不崩溃且能看到对方离开或等待状态。
9. 重新进入 call，B 点击挂断，确认同样行为。
10. 使用非好友访问 `/app/call/:friendId`，确认页面显示无权限状态。

通过标准：

- A/B 能进入同一个一对一 call。
- 授权后麦克风和摄像头可用。
- 麦克风、摄像头、挂断控制可用。
- 任一方挂断后不会导致另一方页面崩溃。
- 非好友不能进入视频通话。
- 浏览器控制台没有影响主流程的 error。
