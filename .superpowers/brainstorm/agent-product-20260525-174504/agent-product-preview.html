A. 项目驾驶舱

以项目为中心管理产品文档、技术文档、Figma、任务、验证和提交记录。

优点：最贴近你的文档流程，容易做出可用第一版。
代价：早期流程编排能力不会特别自由。

B. Agent 流程编排器

以流程节点为中心，让用户配置多个 agent 的顺序、输入、输出和验证门禁。

优点：长期想象空间大，像低代码 agent 平台。
代价：第一版复杂度高，容易陷入抽象设计。

C. AI 开发工作台

像一个可视化 Codex/Claude Code，用户在页面里聊天、看文件、跑任务。

优点：用户感知强，演示效果好。
代价：文件、终端、权限、安全隔离都要很早处理。
我的倾向： 先做 A，再逐步长出 B。也就是第一版先把“一个项目如何被 agent 管好”做扎实，再把每个阶段抽象成可配置流程。
